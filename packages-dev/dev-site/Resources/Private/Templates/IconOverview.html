Every icon the academic extensions register, in both icon registries, as the registries list them at render time - see IconOverviewProcessor. Each icon is a tile with its identifier and its registry, rendered three times: at 1em inside a line of text, at 2rem, and in the text colour of a dark ground, so an icon that is not drawn in currentColor stands out on the dark ground. The frontend registry is rendered the way a frontend template of the extensions renders an icon, with ab:icon and the inline markup. The backend registry is only reachable through core:icon, rendered in its default markup, the one the backend shows: an icon of the core SVG provider is an there and stays dark. Style attributes only: the frontend Content Security Policy of both cores allows them and blocks an inline style element without a nonce. The frontend icon API of academic_base (ACE-595), both of its paths. The icons in the two lists below are not rendered here: the module icon-demo.js of this package asks the icon factory of academic_base for each identifier a slot names and puts the element it gets into the slot, or "not available". The first list is answered from the JSON map rendered next to it, without a request. The second one is not on the page and goes to the endpoint the second map names, in one request for all of them, the core icon among them left out because only the backend registry knows it. data-icon-demo-state on each slot says what happened, for a browser test.
