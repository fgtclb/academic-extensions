Every icon the academic extensions register, as the registry lists it at render time - see IconOverviewProcessor. Each identifier is rendered three times with the markup a frontend template of the extensions uses: at 1em inside a line of text, at 2rem, and in the text colour of a dark ground, so an icon that is not drawn in currentColor stands out in the third column. Style attributes only: the frontend Content Security Policy of both cores allows them and blocks an inline style element without a nonce. The frontend icon API of academic_base (ACE-595), both of its paths. The icons in the two lists below are not rendered here: the module icon-demo.js of this package asks the icon factory of academic_base for each identifier a slot names and puts the element it gets into the slot, or "not available". The first list is answered from the JSON map rendered next to it, without a request; the second one is not on the page and goes to the endpoint the second map names - one request for all of them, the core icon among them refused. data-icon-demo-state on each slot says what happened, for a browser test.
