Every icon the academic extensions register, in both icon registries, as the registries list them at render time - see IconOverviewProcessor. Each icon is a tile with its identifier and its registry, rendered three times: at 1em inside a line of text, at 2rem, and in the text colour of a dark ground, so an icon that is not drawn in currentColor stands out on the dark ground. The frontend registry is rendered the way a frontend template of the extensions renders an icon, with ab:icon and the inline markup. The backend registry is only reachable through core:icon, rendered in its default markup, the one the backend shows: an icon of the core SVG provider is an there and stays dark. Style attributes only: the frontend Content Security Policy of both cores allows them and blocks an inline style element without a nonce.

{data.header}

The group of an identifier decides its registry: action, state and info icons are frontend icons, record, plugin and doktype icons backend icons. Only the icons of the category types are in both. A placeholder in a tile, or an icon that stays dark on the dark ground, is the defect to look for.

Frontend registry ({registry.count} icons)

Configuration/FrontendIcons.php and the category types, rendered with <ab:icon … alternativeMarkupIdentifier="inline" />.

Backend registry ({registry.count} icons)

Configuration/Icons.php and the category types, rendered with <core:icon … /> in its default markup.
