The only place a form control of the profile editor is spelled. It is rendered from three call sites: inline for the permanent profile fields (Field/Editable.html, Field/Select.html, Field/Checkbox.html), once per control type into Partials/Profile/Prototypes.html, and - through those prototypes - for every field of a document editor and of a contact editor. Before this partial existed in that role there were three implementations of one control set and two of them had already drifted; a functional test now asserts that a prototype control and the live control of the same type carry the same tag, the same classes and the same attributes. Arguments: control "input", "textarea", "richText", "select" or "checkbox" prototype true while rendering into Prototypes.html profile the profile (live mode only) field the field definition (live mode only) elementId the id of the control (live mode only) options value => label map of a select (live mode only) rows rows of a textarea autosave render the autosave hook on a checkbox (live mode only) The one branch on "prototype" is below and there is deliberately no second one: in prototype mode the concrete id, name and value are empty and the "data-pe-attr" bindings carry their slot names instead, which the filler of frontend/profile/prototypes.ts resolves. A date is the browser's own control since ACE-552, and which of the three it is follows the field's configured granularity: a full date and a month are native pickers, a year is a number control because no browser has a year input. The field type of the settings graph stays "date" - it is what the endpoint validates and formats by - and `getControlInputType()` turns it into the tag's `type` here. The prototype filler does the same on the other side of the Fluid boundary, in `inputTypeOf()` of `field-clone.ts`: two implementations that have to be kept in step, because nothing enforces that they agree. No shipped profile field is a date; the mapping is here so that one configured by an integrator renders the same control as the timeline and contract dates. No permanent profile field declares a placeholder. The variable exists so that the one control partial spells the attribute once; an empty value takes it off the tag, the same way an empty autocomplete does.
