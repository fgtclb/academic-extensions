The only place a form control of the profile editor is spelled. It is rendered from three call sites: inline for the permanent profile fields (Field/Editable.html, Field/Select.html, Field/Checkbox.html), once per control type into Partials/Profile/Prototypes.html, and - through those prototypes - for every field of a document editor and of a contact editor. Before this partial existed in that role there were three implementations of one control set and two of them had already drifted; a functional test now asserts that a prototype control and the live control of the same type carry the same tag, the same classes and the same attributes. Arguments: control "input", "textarea", "richText", "select" or "checkbox" prototype true while rendering into Prototypes.html profile the profile (live mode only) field the field definition (live mode only) elementId the id of the control (live mode only) options value => label map of a select (live mode only) rows rows of a textarea autosave render the autosave hook on a checkbox (live mode only) The one branch on "prototype" is below and there is deliberately no second one: in prototype mode the concrete id, name and value are empty and the "data-pe-attr" bindings carry their slot names instead, which the filler of frontend/profile/prototypes.ts resolves.
